<h1>The English OpenList: a word list that keeps itself up to date</h1>
{% include article-date.html %}
<p class="article-subtitle">345,162 English words, lowercase a to z, checked against dictionaries every night</p>
<p>The <a href="https://english-openlist.pages.dev/">English OpenList</a> (EOL) is a free list of 345,162 English words, lowercase a to z and nothing else. It&rsquo;s published on <a href="https://huggingface.co/datasets/ryanjosephkamp/english-openlist">Hugging Face</a> under the MIT license and maintained by a GitHub Actions run that checks new candidates against dictionaries every night.</p>
<p>The EOL is made for word games and apps, research, and teaching. But it&rsquo;s <strong>not</strong> just another big text file:</p>
<ul>
<li><strong>Every word has a record:</strong> how it got on the list (from a source, through a check that used a language model, or generated by rule), so you can leave out whatever you don&rsquo;t trust.</li>
<li><strong>It updates itself:</strong> Every night at midnight UTC, a run looks for new words and checks about 1,000 candidates against Merriam-Webster and the Free Dictionary API. Every run gets its own page in the daily log.</li>
<li><strong>Corrections in the open:</strong> A word moves by hand only through a ledger row that names the word, the action, the reason, the method, the source, and the date.</li>
<li><strong>No arbitrary length limit:</strong> Words run from 1 letter to 47, and there&rsquo;s a ready-made &ldquo;Lengths 2 to 45&rdquo; file if you want the shape of a tournament list.</li>
<li><strong>A site to search it:</strong> The whole list loads into the page, so you can search by prefix, suffix, pattern, or regular expression, and open any word for its record.</li>
</ul>
</header>

<h2 id="why-i-built-it">Why I built it</h2>
<p>I built the English OpenList as a free English word list for word games, and it now supplies <a href="https://amordle.vercel.app/">Amordle</a>, <a href="https://ars-magna.pages.dev/">Ars Magna</a>, and <a href="https://ryanjosephkamp.github.io/portfolios/anagram-tiles/">Anagram Tiles</a>.</p>
<p>What a game needs from its list is simple. It has to be free to ship. It has to keep up, because English doesn&rsquo;t stop in 1998. And it has to show its work, because a list that can&rsquo;t say why a word is on it can&rsquo;t say whether to trust it.</p>
<p><strong>So I built one that does all three.</strong> Every word carries a record of how it got on, and every night, a run checks new candidates against dictionaries and publishes the ones they recognize.</p>

<h2 id="the-rule">The rule</h2>
<p>The rule is short: an entry is lowercase a to z and nothing else, the pattern <code>^[a-z]+$</code>, with no length bound. No capitals, spaces, hyphens, apostrophes, digits, or accents.</p>
<p>That makes the list deliberately <strong>not</strong> a tournament word list. It holds the 1-letter words <em>a</em> and <em>i</em>, and words longer than 45 letters, both of which tournament lists leave out. If you want their shape, the &ldquo;Lengths 2 to 45&rdquo; download has it.</p>

<h2 id="how-a-word-gets-on-and-off">How a word gets on, and off</h2>
<p>Each night, the run draws about 1,000 candidates (possibly valid words) from a pool of over 9 million strings and checks whether they exist in Merriam-Webster&rsquo;s Collegiate and Medical dictionaries and the Free Dictionary API. A word recognized by a dictionary is promoted to the list. A word whose lookup is refused or rate-limited simply waits for another night, and nothing records it as rejected.</p>
<p>The only other way a word moves is by hand, through a correction ledger. That&rsquo;s how the list made its biggest correction: in August 2026, 33,594 forms its synthetic engine had made algorithmically (comparatives and superlatives, gerund plurals, verb forms, and agent plurals) were moved off the list, decided by the inflections that Merriam-Webster records for their stems.</p>
<p>Every one of them is queued to be checked again, because <strong>no word is ever off the list for good</strong>. A string absent from a dictionary today might be added to it tomorrow. But once a word enters the EOL, it never leaves, unless it was originally included by mistake.</p>

<h2 id="what-decided-each-word">What decided each word</h2>
<p>Not every word entered the EOL the same way. Each word&rsquo;s record says how it got on, sorted into four values:</p>
<ul>
<li><strong>From a source (176,222):</strong> It came from a word list, a dictionary, or a glossary of a field such as medicine. No language model or generator decided it.</li>
<li><strong>Checked with a model (131,226):</strong> It passed a check of several steps, and a language model was one of the steps.</li>
<li><strong>A model&rsquo;s call alone (6,471):</strong> A language model judged it a word, and no other check backs that.</li>
<li><strong>Generated by rule (31,243):</strong> The synthetic engine made it by rule, for example by adding a prefix or a suffix to a word already on the list.</li>
</ul>
<p>If you&rsquo;d rather not ship words a model vouched for, or words a program made, leave them out. That&rsquo;s the point of keeping the record.</p>

<h2 id="night-by-night">Night by night</h2>
<p>The nightly run adds a few words a night, not thousands. It&rsquo;s there to keep up with English, not to pad the count. The 100+ runs in the daily log, from May 14 to the present, each have a page with the words they added and where they came from.</p>

<h2 id="the-catch">The catch</h2>
<p>A list like this is only useful if you know where it falls short, so here it is up front.</p>
<ul>
<li><strong>Lowercase a to z, nothing else.</strong> No hyphenated compounds, accented loanwords, contractions, or multiword terms. That&rsquo;s by design.</li>
<li><strong>Not a tournament list.</strong> It holds words that tournament lists leave out, so it won&rsquo;t settle a game of Scrabble.</li>
<li><strong>Some words rest on a model, and some were made by rule.</strong> 137,697 words were decided with a language model, 6,471 of them by the model&rsquo;s call alone, and 31,243 came from the synthetic engine. Every one is marked, so you can leave them out.</li>
<li><strong>It changes every night.</strong> If you need a list that holds still, pin a revision of the dataset.</li>
<li><strong>No definitions.</strong> A word&rsquo;s record says how it got on, not what it means. Its panel on the site links to dictionaries that do.</li>
</ul>

<h2 id="use-it">Use it</h2>
<p>The list is plain text, 1 word a line, sorted. Grab it with a shell:</p>
<pre><code>curl -sL -o merged_valid_words.txt \
  https://huggingface.co/datasets/ryanjosephkamp/english-openlist/resolve/main/data/merged_valid_words.txt</code></pre>
<p>Or, in Python:</p>
<pre><code>from huggingface_hub import hf_hub_download

path = hf_hub_download(
    "ryanjosephkamp/english-openlist",
    "data/merged_valid_words.txt",
    repo_type="dataset",
)
words = open(path, encoding="utf-8").read().split()
print(len(words))  # 345,162, as of this post</code></pre>
<p>The dataset also holds every word&rsquo;s record (<code>data/merged_valid_dict.json</code>), the candidates not on the list (<code>data/merged_invalid_words.txt</code>), and word-game files by length (<code>latest/brrrdle/</code>). The list changes whenever the nightly run publishes, so if you need it to hold still, put a revision of the dataset in place of <code>main</code>.</p>
<p>On the <a href="https://english-openlist.pages.dev/">site</a>, you can search the list, open any word&rsquo;s record, read the <a href="https://english-openlist.pages.dev/blog/">daily log</a> (with an <a href="https://english-openlist.pages.dev/feed.xml">RSS feed</a>), and download 2 ready-made subsets: the list <a href="https://english-openlist.pages.dev/downloads/">without the synthetic engine</a> (313,919 words) and lengths 2 to 45 (345,157 words).</p>

<h2 id="under-the-hood">Under the hood</h2>
<p>The English OpenList is 3 things: a Python program that runs every night, a set of plain files on Hugging Face, and a static site that loads the whole list into your browser.</p>
<h3>The nightly run: Python on GitHub Actions</h3>
<ul>
<li><strong>Python 3.12, on a schedule:</strong> The run is a GitHub Actions workflow that starts at midnight UTC. GitHub runs it for free on a public repository, so the list keeps up with no server of my own.</li>
<li><strong>Small, plain dependencies:</strong> <code>httpx</code> calls the dictionary APIs, <code>tenacity</code> retries a request politely, <code>feedparser</code> reads the words-of-the-day feeds, <code>orjson</code> handles the 280 MB record file, and <code>huggingface_hub</code> publishes. The lock file pins every package by its hash.</li>
<li><strong>It fails loudly:</strong> A step that fails stops the run, and a refused or rate-limited lookup is never recorded as a rejection. A dry-run switch runs everything except the publish.</li>
<li><strong>Corrections as CSV files:</strong> Every change made by hand is a row in a ledger in the repository, so it&rsquo;s reviewed in a pull request like code, and its history is the repository&rsquo;s.</li>
</ul>
<h3>The data: plain text, versioned</h3>
<p>The list is a sorted text file, 1 word a line, because every language can read that in 1 line of code. Hugging Face hosts it for free and keeps a revision for every publish, so you can pin one; each word&rsquo;s record sits beside the list as JSON.</p>
<h3>The site: the whole list in your browser</h3>
<ul>
<li><strong>Astro 7 and React 19, in TypeScript:</strong> The pages are static HTML. The search and the charts are React components that load only where they&rsquo;re used.</li>
<li><strong>A compact binary list:</strong> The list ships front-coded: since it&rsquo;s sorted, each word stores only how much it shares with the word before it, plus the rest. That makes it about 8 times smaller over the wire than the text file, and it decodes in a single pass in milliseconds.</li>
<li><strong>Search off the main thread:</strong> A Web Worker holds the decoded list as 1 flat table rather than hundreds of thousands of separate strings, so prefix, suffix, pattern, and regular-expression searches run without freezing the page.</li>
<li><strong>Built from the dataset:</strong> A Node tool streams the dataset&rsquo;s files, the 280 MB record included, into the site&rsquo;s data and the daily log at build time. A deploy workflow publishes the result to Cloudflare Pages after every nightly run.</li>
</ul>
<p>Every pull request runs the Python tests and the site&rsquo;s tests and type checks on GitHub Actions.</p>
